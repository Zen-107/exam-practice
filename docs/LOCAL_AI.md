# ใช้ AI ในเครื่องตัวเอง (LM Studio / Ollama / vLLM / อื่นๆ)

สำหรับคนที่มีคอมแรงๆ (มีการ์ดจอ หรือ Mac รุ่น M) และอยากให้ตัวตรวจคำตอบทำงานบนเครื่องตัวเอง
ไม่ต้องใช้โควตา AI ฟรีบน cloud ใช้ได้ไม่จำกัด และคำตอบไม่ถูกส่งออกนอกเครื่อง

มี 2 แบบ:

| แบบ | ใคร | ต้องทำอะไร |
|---|---|---|
| **A. ตั้งในหน้าเว็บ** | เพื่อนที่เปิดเว็บที่ deploy ไว้ | เปิด AI ในเครื่อง แล้วกดตั้งค่าในเว็บ — ไม่ต้องรันโค้ด |
| **B. ตั้งใน `.env`** | คนดูแลเว็บ / คนที่รันแอปเอง | ตั้งตัวตรวจหลักของเว็บ (ใช้ร่วมกันทุกคน) |

---

## แบบ A — เพื่อนใช้เว็บที่ deploy ไว้ แล้วให้ตรวจด้วย AI ในเครื่องตัวเอง

เบราว์เซอร์ของเพื่อนจะเรียก AI ในเครื่องเพื่อน (`http://localhost:…`) โดยตรง คำตอบไม่ผ่าน server ของเว็บ
ค่าที่ตั้งเก็บในเบราว์เซอร์ของเพื่อนแต่ละคน

1. **เปิด AI ในเครื่อง** — เลือกโปรแกรมเดียวจาก[ข้อ 3](#3-เลือกตัวรัน-ai) (LM Studio ง่ายสุด)
   และ **ต้องอนุญาตให้เว็บเรียกได้ (CORS)** ทุกโปรแกรม:
   - **LM Studio:** หน้า Developer → Settings → เปิด **Enable CORS**
   - **Ollama:** ตั้ง `OLLAMA_ORIGINS` เป็นที่อยู่เว็บ (หน้าตั้งค่าในเว็บมีคำสั่งที่เติมที่อยู่ให้แล้ว กดคัดลอกได้เลย) แล้วปิด-เปิด Ollama ใหม่
   - **vLLM:** เติม `--allowed-origins '["<ที่อยู่เว็บ>"]'`
   - **llama.cpp:** อนุญาตอยู่แล้ว
2. **เปิดเว็บ** ด้วย Chrome หรือ Edge แล้วกด **ไอคอนเฟือง** (มุมขวาบน) หรือลิงก์ **ใช้ AI ในเครื่องตัวเอง** ที่หน้าแรก
3. กด **AI ในเครื่องของฉัน** → เลือกโปรแกรม (LM Studio / Ollama / vLLM / llama.cpp / Jan)
4. กด **ดึงรายชื่อโมเดล** แล้วเลือกโมเดล
5. กด **ทดสอบการเชื่อมต่อ** — ถ้าเบราว์เซอร์ถามว่าให้เว็บ **เข้าถึงอุปกรณ์/แอปในเครือข่ายท้องถิ่น** ให้กด **อนุญาต**
   ต้องขึ้นเครื่องหมายถูก 2 ข้อ และ "พร้อมใช้!"
6. ไปทำข้อสอบได้เลย — หน้าผลจะเขียนว่า **ตรวจด้วย AI ในเครื่องคุณ · ชื่อโมเดล**

ถ้าวันไหนปิด AI ในเครื่อง เว็บจะใช้ตัวตรวจของเว็บแทนให้เอง (ปิดได้ใน "ตั้งค่าขั้นสูง")
อยากกลับไปใช้ของเว็บตามปกติ กด **ตัวตรวจของเว็บ** ในหน้าตั้งค่า

> หน้าตั้งค่ามีโหมด **API key ของฉัน** ด้วย (Groq / Gemini / OpenRouter) สำหรับเพื่อนที่อยากใช้โควตาของตัวเอง
> key เก็บในเบราว์เซอร์นั้นเท่านั้น — บางเจ้าไม่ยอมให้เว็บเรียกตรงจากเบราว์เซอร์ ถ้าทดสอบไม่ผ่านแปลว่าใช้วิธีนี้กับเจ้านั้นไม่ได้

**ปัญหาที่เจอบ่อย (แบบ A)**

| อาการ | วิธีแก้ |
|---|---|
| ทดสอบข้อแรกไม่ผ่าน "ต่อไม่ติด" | เปิด server หรือยัง · เปิด CORS / ตั้ง `OLLAMA_ORIGINS` แล้ว **ปิด-เปิดโปรแกรมใหม่** หรือยัง · กดอนุญาตเครือข่ายท้องถิ่นในเบราว์เซอร์หรือยัง · port ตรงไหม |
| ใช้ Safari แล้วไม่ผ่าน | Safari มักบล็อกการเรียก `http://localhost` จากเว็บ https — ใช้ Chrome หรือ Edge |
| ข้อสองไม่ผ่าน (404) | ชื่อโมเดลไม่ตรง — กดดึงรายชื่อโมเดลใหม่ |
| ช้า / หมดเวลา | ใช้โมเดลเล็กลง หรือเพิ่ม "รอคำตอบนานสุด" ใน ตั้งค่าขั้นสูง |

## 1. AI ในแอปนี้ใช้ทำอะไร

| งาน | ใช้อะไร | ถ้าไม่มี |
|---|---|---|
| **ตรวจคำตอบ** (ข้อเขียน) | LLM แบบ OpenAI-compatible — ในเครื่องหรือ cloud | ตรวจด้วยคำสำคัญแทน (หยาบ) |
| **ถอดเสียง** (โหมดพูด) | ตัวถอดเสียงของเบราว์เซอร์ (ฟรี) หรือ Whisper | พิมพ์ตอบ |
| **แก้คำที่ถอดเพี้ยน** (กดปุ่มเอง) | LLM ตัวเดียวกับตัวตรวจ | แก้เองในช่อง |

ข้อตัวเลข จับคู่ และเรียงลำดับ ตรวจด้วยโค้ด ไม่ใช้ AI

**ลำดับที่แอปเรียกตัวตรวจ:** `GRADER_*` (เช่น AI ในเครื่อง) → `GRADER_FALLBACK_*` (ถ้าตั้ง) → Groq (ถ้ามี `GROQ_API_KEY`)
ตัวแรกปิดอยู่ ช้าเกิน หรือโควตาเต็ม จะขยับไปตัวถัดไปเอง

   ```powershell
   powershell -c "irm bun.sh/install.ps1 | iex"
   ```

   ```powershell
   bun install
   ```

   ```powershell
   copy .env.example .env
   ```

## 3. เลือกตัวรัน AI

ทุกตัวด้านล่างเปิด API แบบเดียวกับ OpenAI (`/v1/chat/completions`) แอปจึงใช้ได้หมด เลือกตัวเดียวพอ

### A. LM Studio (ง่ายสุด มีหน้าจอให้กด)

เหมาะกับ Windows / Mac ที่ไม่อยากพิมพ์คำสั่ง

1. ดาวน์โหลดจาก <https://lmstudio.ai> แล้วติดตั้ง
2. **โหลดโมเดล:** กดแท็บ **Discover** (รูปแว่นขยาย แถบซ้าย)
   - พิมพ์ค้นหา `qwen2.5 7b instruct` (หรือดูรุ่นที่เหมาะกับเครื่องใน[ข้อ 5](#5-เลือกโมเดลให้พอดีกับเครื่อง))
   - เลือกไฟล์ที่ลงท้าย **Q4_K_M** แล้วกด **Download** รอจนเสร็จ
3. **เปิด server:** กดแท็บ **Developer** (ไอคอน `>_` แถบซ้าย)
   - ด้านบนกด **Select a model to load** แล้วเลือกโมเดลที่โหลดไว้
   - ตอนโหลด ตั้ง **Context Length** อย่างน้อย **8192** (ข้อยาวๆ จะได้ไม่ถูกตัด)
   - เปิดสวิตช์ **Status: Running** (หรือปุ่ม **Start Server**) จะขึ้นว่าเปิดที่ `http://localhost:1234`
4. **คัดลอกชื่อโมเดล:** ในหน้า Developer มีชื่อโมเดล (API identifier) เช่น `qwen2.5-7b-instruct` ให้กดคัดลอก
5. ไปทำ[ข้อ 4](#4-ตั้งค่า-env-แล้วเปิดแอป) โดยใช้
   ```env
   GRADER_BASE_URL=http://localhost:1234/v1
   GRADER_MODEL=qwen2.5-7b-instruct
   ```

> ชื่อปุ่มอาจต่างกันเล็กน้อยตามเวอร์ชันของ LM Studio
> ถ้าจะให้เครื่องอื่นในวงแลนเรียกได้ ให้เปิด **Serve on Local Network** ใน Settings ของหน้า Developer ด้วย

### B. Ollama

เบา รันเป็น background เอง เหมาะกับคนพิมพ์คำสั่งได้

1. ดาวน์โหลดจาก <https://ollama.com> แล้วติดตั้ง (ติดตั้งเสร็จจะรัน server ที่ `http://localhost:11434` ให้อัตโนมัติ)
2. โหลดโมเดล — เปิด terminal แล้วรัน
   ```powershell
   ollama pull qwen2.5:7b
   ```
3. ลองคุยดู (ถ้าตอบได้แปลว่าพร้อม กด `Ctrl+D` เพื่อออก)
   ```powershell
   ollama run qwen2.5:7b "สวัสดี ตอบเป็นภาษาไทย"
   ```
4. **ขยาย context** (สำคัญ — ค่าเริ่มต้นของ Ollama สั้น ข้อยาวๆ จะถูกตัด): ตั้งตัวแปรระบบ `OLLAMA_CONTEXT_LENGTH=8192` แล้วปิด-เปิด Ollama ใหม่
   หรือถ้าไม่อยากตั้ง ให้ใส่ `GRADER_ANSWER_KEY_CHARS=2000` ใน `.env` แทน (ส่งเฉลยให้ตัวตรวจสั้นลง)
5. ไปทำ[ข้อ 4](#4-ตั้งค่า-env-แล้วเปิดแอป) โดยใช้
   ```env
   GRADER_BASE_URL=http://localhost:11434/v1
   GRADER_MODEL=qwen2.5:7b
   ```

### C. vLLM (การ์ดจอ NVIDIA)

เร็วที่สุด เหมาะกับเครื่องที่มีการ์ดจอ NVIDIA บน Linux หรือ Windows ผ่าน WSL2 หรือเครื่อง server ของเพื่อน

1. ติดตั้ง (ใน Linux / WSL2 ที่มี Python)
   ```bash
   pip install vllm
   ```
2. เปิด server (ครั้งแรกจะดาวน์โหลดโมเดลจาก Hugging Face)
   ```bash
   vllm serve Qwen/Qwen2.5-7B-Instruct --port 8000 --max-model-len 8192
   ```
   ถ้าจะให้เครื่องอื่นเรียกได้ เติม `--host 0.0.0.0`
3. ไปทำ[ข้อ 4](#4-ตั้งค่า-env-แล้วเปิดแอป) โดยใช้
   ```env
   GRADER_BASE_URL=http://localhost:8000/v1
   GRADER_MODEL=Qwen/Qwen2.5-7B-Instruct
   ```
   (ถ้า vLLM อยู่เครื่องเพื่อน ใช้ IP ของเครื่องนั้นแทน `localhost` เช่น `http://192.168.1.20:8000/v1`)

### D. ตัวอื่นๆ

ตัวไหนก็ได้ที่มี `/v1/chat/completions` แบบ OpenAI ตั้ง `GRADER_BASE_URL` ให้ลงท้ายด้วย `/v1`

| ตัวรัน | คำสั่ง/วิธีเปิด | `GRADER_BASE_URL` |
|---|---|---|
| llama.cpp | `llama-server -m model.gguf --port 8080 -c 8192` | `http://localhost:8080/v1` |
| Jan | Settings → Local API Server → Start | `http://localhost:1337/v1` |
| LocalAI | ตามคู่มือ LocalAI | `http://localhost:8080/v1` |
| text-generation-webui | เปิดด้วย `--api` | `http://localhost:5000/v1` |

ถ้า server ต้องใช้ key ใส่ใน `GRADER_API_KEY` ถ้าเป็นเครื่องในบ้าน/วงแลน (`localhost`, `127.x`, `192.168.x`, `10.x`) ไม่ต้องใส่ key
ถ้าเป็นชื่อโดเมนอื่นที่ไม่ใช้ key ให้ตั้ง `GRADER_KEYLESS=true`

## 4. ตั้งค่า .env แล้วเปิดแอป

1. เปิดไฟล์ `exam-practice/.env` แล้วใส่ 2 บรรทัดตามตัวรันที่เลือก เช่น LM Studio
   ```env
   GRADER_BASE_URL=http://localhost:1234/v1
   GRADER_MODEL=qwen2.5-7b-instruct
   ```
2. (แนะนำ) เช็คว่า server ตอบจริง — ต้องเห็นรายชื่อโมเดล
   ```powershell
   curl http://localhost:1234/v1/models
   ```
3. เปิดแอป (ถ้าเปิดอยู่แล้ว กด `Ctrl+C` แล้วเปิดใหม่ เพราะ `.env` อ่านตอนเปิดเท่านั้น)
   ```powershell
   bun run dev
   ```
4. เปิด <http://localhost:5173> แล้วดูกล่องล่างสุดของหน้าแรก ต้องขึ้น
   **ตัวตรวจ AI พร้อม (qwen2.5-7b-instruct · ในเครื่อง)**
5. ลองทำข้อหนึ่งแล้วกด **ส่งตรวจ** — ด้านบนผลตรวจต้องเขียนว่า **ตรวจด้วย AI**
   ครั้งแรกอาจช้า 10–60 วินาที เพราะโมเดลกำลังโหลดเข้าการ์ดจอ

> มี `GROQ_API_KEY` อยู่แล้ว? แอปจะใช้ AI ในเครื่องก่อน ถ้าปิดเครื่อง AI หรือมันค้าง จะสลับไป Groq ให้เอง
> อยากใช้แต่ในเครื่องเท่านั้น ให้ใส่ `GRADER_GROQ_FALLBACK=false`

## 5. เลือกโมเดลให้พอดีกับเครื่อง

ดู **VRAM ของการ์ดจอ** (Windows: Task Manager → Performance → GPU → Dedicated GPU memory) หรือ **RAM** ของ Mac รุ่น M

| หน่วยความจำ | โมเดลแนะนำ (Q4) | หมายเหตุ |
|---|---|---|
| 6–8 GB | Qwen2.5 7B Instruct, Gemma 3 4B | ใช้ได้ แต่ตัดสินพลาดบ่อยกว่า |
| 12–16 GB | **Qwen2.5 14B Instruct**, Gemma 3 12B | สมดุลที่สุด แนะนำ |
| 24 GB ขึ้นไป | Qwen2.5 32B Instruct | ใกล้เคียง AI บน cloud |

- ต้องเป็นรุ่น **Instruct** (ไม่ใช่ Base) และควรเก่งภาษาไทย — Qwen และ Gemma อ่านไทยได้ดี หรือลองค้นคำว่า `typhoon` (โมเดลที่ปรับมาเพื่อภาษาไทยโดยเฉพาะ)
- โมเดลแบบ "คิดก่อนตอบ" (เช่น Qwen3, DeepSeek-R1) ใช้ได้ แอปตัดส่วน `<think>` ทิ้งให้ แต่จะช้ากว่า
- โมเดลเล็กอาจให้คะแนนพลาด ใช้ปุ่ม **ฉันตอบประเด็นนี้แล้ว / ยังไม่ได้ตอบ** ในหน้าผลแก้ได้

## 6. แชร์ให้เพื่อนในวง Wi-Fi เดียวกัน

**แบบที่ 1 — เพื่อนเปิดแอปจากเครื่องเรา**

1. รัน `bun run dev` ในเครื่องที่มี AI — terminal จะแสดงลิงก์ `Network: http://192.168.x.x:5173`
2. ส่งลิงก์นั้นให้เพื่อนที่ต่อ Wi-Fi เดียวกัน
3. ถ้าเพื่อนเปิดไม่ได้ ให้กด **Allow** ตอน Windows Firewall ถาม (หรืออนุญาต Bun ใน Firewall)

ข้อจำกัด: เบราว์เซอร์อนุญาตให้ใช้ไมค์เฉพาะ `localhost` หรือ `https` เพื่อนที่เข้าผ่านลิงก์ IP จึงต้องใช้ **โหมดพิมพ์**

**แบบที่ 2 — ใช้ AI จากเครื่องเพื่อน (เพื่อนเปิด server ให้)**

1. เพื่อนเปิด LM Studio (เปิด **Serve on Local Network**) หรือ `vllm serve … --host 0.0.0.0`
2. เพื่อนบอก IP ของเครื่องตัวเอง (Windows: `ipconfig` → IPv4 Address)
3. เราตั้ง `.env` เป็น IP ของเพื่อน เช่น `GRADER_BASE_URL=http://192.168.1.20:1234/v1` แล้วเปิดแอปเอง

## 7. ถอดเสียงในเครื่อง (ไม่บังคับ)

ปกติโหมดพูดใช้ตัวถอดเสียงของเบราว์เซอร์ (Chrome / Edge / Safari) อยู่แล้ว ฟรีและไม่ต้องตั้งอะไร
LM Studio และ Ollama **ถอดเสียงไม่ได้** ถ้าอยากใช้ Whisper ในเครื่อง ต้องมี server ที่มี `/v1/audio/transcriptions` เช่น Speaches หรือ LocalAI แล้วตั้ง

```env
STT_BASE_URL=http://localhost:8000/v1
STT_MODEL=<ชื่อโมเดล whisper ตามที่ server นั้นใช้>
```

## 8. วิธีประหยัด AI

แอปช่วยประหยัดให้อัตโนมัติ:

- **ใช้ AI ในเครื่องก่อน** — โควตา cloud ใช้เฉพาะตอนเครื่องเราล่ม
- **ไม่ตรวจคำตอบเดิมซ้ำ** — ส่งคำตอบเดิมกับข้อเดิม จะใช้ผลครั้งก่อน (ขึ้นว่า "ใช้ผลตรวจเดิม")
- **ข้อตัวเลข / จับคู่ / เรียงลำดับ** ตรวจด้วยโค้ด ไม่ใช้ AI
- **คำตอบว่าง** ไม่ส่งไปตรวจ
- **key หลายตัว** — ใช้ตัวแรกจนโควตาเต็มแล้วค่อยใช้ตัวถัดไป (Groq ใส่ได้ 9 ช่อง `GROQ_API_KEY`, `_2` … `_9`)

ตั้งเพิ่มได้ใน `.env`:

| ตั้งค่า | ผล |
|---|---|
| `GRADER_ANSWER_KEY_CHARS=2000` | ส่งเฉลยให้ตัวตรวจสั้นลง → ใช้ token น้อยลง เร็วขึ้น (ตั้ง `0` = ไม่ส่งเฉลยเลย ใช้แต่ rubric) |
| `STT_CORRECT=false` | ไม่ให้ AI แก้คำที่ถอดเสียงอัตโนมัติ |
| `GRADER_GROQ_FALLBACK=false` | ไม่ใช้ Groq เป็นตัวสำรอง (ใช้แต่ในเครื่อง) |

และตอนใช้งาน:

- ใช้ตัวถอดเสียงของเบราว์เซอร์แทน Whisper (ฟรี ไม่ใช้โควตา)
- กดปุ่ม **ให้ AI แก้คำที่ถอดเพี้ยน** เฉพาะตอนจำเป็น — แก้เองในช่องได้
- ตอบเป็นช่องสั้นๆ ตามที่แอปแบ่งให้ ข้อความสั้นใช้ token น้อยกว่า

## 9. แก้ปัญหา

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| หน้าแรกขึ้น **ตัวตรวจ AI ไม่พร้อม** | ยังไม่ได้ตั้ง `GRADER_BASE_URL` หรือแก้ `.env` แล้วยังไม่เปิด `bun run dev` ใหม่ |
| ผลตรวจขึ้น **ต่อเซิร์ฟเวอร์ AI ไม่ได้** | server ยังไม่เปิด / port ผิด — ลอง `curl http://localhost:1234/v1/models` |
| ขึ้น **ตัวตรวจ AI ใช้ไม่ได้ (bad_model_output)** | โมเดลตอบไม่เป็น JSON — ใช้โมเดลใหญ่ขึ้น (14B+) หรือรุ่น Instruct |
| ขึ้น **upstream_error … 400** ทุกครั้ง | ชื่อ `GRADER_MODEL` ไม่ตรงกับที่ server โหลดไว้ — คัดลอกจาก `/v1/models` |
| ช้ามาก / หมดเวลา | เพิ่ม `GRADER_TIMEOUT_MS=300000`, ใช้โมเดลเล็กลง, หรือตั้ง `GRADER_ANSWER_KEY_CHARS=2000` |
| ข้อยาวๆ ได้ผลแปลก / error เรื่อง context | เพิ่ม Context Length ของ server เป็น 8192 ขึ้นไป หรือลด `GRADER_ANSWER_KEY_CHARS` |
| เพื่อนเปิดลิงก์ IP ไม่ได้ | อนุญาต Bun ใน Windows Firewall และต้องอยู่ Wi-Fi เดียวกัน |
| เพื่อนกดไมค์ไม่ได้ | เบราว์เซอร์ให้ใช้ไมค์เฉพาะ localhost/https — ให้เพื่อนใช้โหมดพิมพ์ |
